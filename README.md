# LEVO KG — интернет-магазин и панель управления

Frontend на **Next.js 15 App Router**, React 19, TypeScript и TanStack Query. Данные магазина и админки запрашиваются у отдельного NestJS API через `NEXT_PUBLIC_API_URL`.

## Запуск

Требуется Node.js 20.9+.

```bash
npm install
# создайте .env.local и укажите URL API:
# NEXT_PUBLIC_API_URL=http://localhost:3001/api/v1
npm run dev
```

Перед публикацией выполните `npm run lint` и `npm run build`.

## Структура проекта

- `app/` — маршруты, layouts, SEO metadata и sitemap. Файлы маршрутов должны оставаться тонкими.
- `app/styles/` — глобальные стили по зонам интерфейса; `app/globals.css` — единая точка импорта.
- `components/` — UI-компоненты, сгруппированные по назначению:
  - `admin/analytics/` — панель статистики;
  - `admin/managers/` — создание и список менеджеров;
  - `analytics/` — клиентский трекер просмотров страниц;
  - `theme/` — провайдер и переключатель темы.
- `hooks/` — клиентские React Query hooks и интерактивное состояние.
- `lib/api/` — типизированные клиенты к NestJS API; UI не должен самостоятельно собирать HTTP-запросы.
- `lib/analytics/` — отправка анонимных событий просмотров.
- `types/` — общие TypeScript-контракты.

## Server Components и Client Components

По умолчанию страницы и layouts App Router — **Server Components**. Не добавляйте `'use client'` в файл без необходимости.

Client Components оправданы, когда требуются `useState`, `useEffect`, обработчики событий, React Query, localStorage, browser APIs или контекст темы. Сейчас интерактивная шапка, переключатель темы, админские формы/таблицы и трекер просмотров клиентские. Footer переведён в Server Component: список категорий запрашивается на сервере с revalidation 300 секунд. Не импортируйте модуль авторизации, использующий localStorage, в серверные компоненты.

Для новых страниц сначала выносите получение данных в серверную функцию или route-level Server Component. Клиенту передавайте только необходимые сериализуемые данные и интерактивные обработчики.

## Единая дизайн-система

Основные токены определены в `app/styles/01-base.css`:

- Цвета: `--ink`, `--muted`, `--paper`, `--surface`, `--surface-muted`, `--line`, `--accent`.
- Геометрия: `--page`, `--content-max`, `--radius-sm/md/lg`, `--control-height`.
- Отступы и эффекты: `--space-1/2/3/4/6/8`, `--shadow-card`.

Используйте токены вместо разрозненных цветов и размеров. `--page` задаёт ширину основного контента; существующие медиазапросы задают единые responsive-переходы. Новые кнопки, поля, карточки и панели должны переиспользовать общие классы и токены, а не дублировать правила.

Переключатель светлой/тёмной темы расположен в шапке. Предпочтение хранится в localStorage, а корневой элемент получает `data-theme="light"` или `data-theme="dark"`. При добавлении новых CSS-правил используйте переменные, чтобы обе темы оставались читаемыми. Проверьте, что контраст, focus states и картинки выглядят корректно в обеих темах.

## Панель администратора

- `/admin` — обзор каталога.
- `/admin/products` — товары.
- `/admin/catalogs` — категории.
- `/admin/analytics` — статистика посещаемости.
- `/admin/managers` — создание и просмотр менеджеров.

Ограничение доступа только на клиенте не является защитой. Каждая административная операция должна быть проверена на NestJS backend с JWT и серверным guard, включая проверку роли `ADMIN`.

### Создание менеджеров

UI использует защищённые NestJS endpoint’ы. Существующие маршруты и усиленная DTO-валидация находятся в [backend PR](https://github.com/akkunov/levo-sever/pull/1); разверните его, прежде чем использовать создание менеджеров в production:

- `GET /admin/users` — защищённый список пользователей; frontend отображает только роль `MANAGER`.
- `POST /admin/users` — защищённое создание пользователя с `role: "MANAGER"`.

Backend должен проверять роль ADMIN, валидировать имя/email/пароль, хешировать пароль через Argon2 или bcrypt, не возвращать password hash и записывать аудит создания пользователя. Пароль не следует логировать или повторно показывать после успешного создания.

## Аналитика — backend PR и хранилище

Клиентский компонент отправляет анонимный просмотр страницы на `POST /analytics/events`: path, title, origin referrer и случайный session ID из sessionStorage. Время события ставит сервер. Админская панель читает `GET /analytics/admin/summary?period=7d`. Endpoint’ы, модель и миграция добавлены в [backend PR](https://github.com/akkunov/levo-sever/pull/1); данные появятся после его развёртывания и применения миграции.

Ожидаемый ответ:

```json
{
  "visitors": 120,
  "pageViews": 430,
  "productViews": 160,
  "popularProducts": [
    { "productId": 41, "productTitle": "Example product", "views": 38 }
  ],
  "period": {
    "from": "2026-10-16T00:00:00.000Z",
    "to": "2026-10-23T00:00:00.000Z"
  }
}
```

Frontend намеренно показывает ошибку API, если backend ещё не развёрнут: он не генерирует фиктивную статистику и не сообщает об успешном создании менеджера, когда API вернул ошибку. События не блокируют навигацию; пути `/admin` и `/api` не отслеживаются. Перед production ограничьте срок хранения событий, не собирайте лишние персональные данные и обновите политику конфиденциальности в соответствии с применимыми требованиями.

## SEO и производительность

- Метаданные задавайте в серверных route-файлах через `metadata` или `generateMetadata`.
- Используйте `next/image` с корректными `sizes`, осмысленным `alt` и настроенными remote patterns.
- Не добавляйте `'use client'` целым страницам ради одного интерактивного блока: выделяйте этот блок в отдельный компонент.
- При добавлении индексируемого маршрута обновляйте sitemap.

npm run lint

Этот репозиторий содержит frontend; миграции и контроллеры отдельного NestJS backend должны быть внесены и протестированы отдельно.
